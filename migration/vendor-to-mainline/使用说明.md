# Mi Box 4 从 Vendor U-Boot 迁移到 Mainline U-Boot

本目录生成的迁移盘用于已经刷入旧 Vendor 分支镜像的 Mi Box 4。旧
U-Boot 只负责从 USB 执行 `aml_autoscript`/`s905_autoscript` 并启动
LibreELEC；整个过程不加载 `u-boot.ext`。写入 eMMC 的目标镜像则包含
完整 Mainline U-Boot FIP。

## 写入 USB 引导盘

生成文件位于 `output/`，文件名以 `-vendor-migration.img` 结尾。请选择
至少 2 GB 的 USB 盘。Windows 可使用 Rufus、balenaEtcher 或
Win32DiskImager，以磁盘镜像/DD 模式写入，不能把 `.img` 当作普通文件
复制到盘中。

Linux 下可使用：

```sh
sudo dd if=LibreELEC-AMLGX.aarch64-12.2-mibox4-vendor-migration.img \
  of=/dev/sdX bs=4M status=progress conv=fsync
```

`/dev/sdX` 必须是整个 USB 磁盘，不能是 `/dev/sdX1`；写入前务必核对
设备名。

## 从旧系统启动

1. 关闭盒子，插入迁移 USB 盘，再冷启动。已安装过旧 Vendor
   LibreELEC 的设备通常会自动扫描 USB 上的 `s905_autoscript`。
2. 如果设备仍在 Android，可插入 USB 后执行 `adb shell reboot update`。
   第一次执行 `aml_autoscript` 时会保存启动环境并自动重启一次。
3. LibreELEC 第一次从新 USB 启动时可能扩展 `/storage` 并再次重启；等待
   它完整启动后再操作。

通过 SSH 确认系统确实从 USB 运行：

```sh
findmnt /flash
findmnt /storage
```

两者都不能位于将要覆盖的 eMMC。然后运行：

```sh
sh /flash/install-to-emmc.sh
```

脚本会校验内嵌的原始镜像，要求输入 `MIBOX4-MIGRATE`，先把 eMMC 前
512 MiB、`boot0` 和 `boot1` 备份到 USB `/storage`，然后将原始完整镜像
解压写入 eMMC，并对写入内容执行完整 SHA-256 校验。完成后执行：

```sh
poweroff
```

拔掉 USB，断电后重新上电。此后由 eMMC 中的 Mainline U-Boot FIP 直接
启动。

## 重要警告

- 操作会删除 Android、Vendor MPT、Recovery 和 eMMC 上的全部数据。
- 不要使用 LibreELEC `.tar` 更新完成这次迁移；`.tar` 不会替换磁盘开头
  的完整 FIP。
- 安装脚本不会改写 eMMC 的硬件 `boot0`/`boot1` 区域，但会先备份它们。
- 如果 `/storage` 可用空间不足 600 MiB，脚本会拒绝执行；请使用更大的
  USB 盘并让首次扩容完成。
